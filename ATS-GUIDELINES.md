# What an ATS-Friendly Resume Needs

A complete checklist covering structure, formatting, content, and technical file requirements.

---

## 1. File Format

- [ ] Save as **.docx** or **standard PDF** (not scanned/image-based PDF)
- [ ] Avoid `.pages`, `.odt`, or other uncommon formats
- [ ] File name should be professional: `FirstName-LastName-Resume.pdf` (avoid "Final_v3_edited.pdf")
- [ ] If the job posting specifies a format, follow it exactly

---

## 2. Layout & Structure

- [ ] **Single column** layout — multi-column resumes often get scrambled by parsers reading left-to-right, line-by-line
- [ ] No tables for layout (parsers may skip table content entirely or read it out of order)
- [ ] No text boxes — content inside text boxes is frequently dropped
- [ ] No headers/footers for critical info (name, contact details) — many parsers skip these regions entirely
- [ ] Reverse-chronological order (most recent experience first) — the format ATS and recruiters expect
- [ ] Consistent margins (0.5"–1") and page size (A4 or Letter, matching region)
- [ ] Keep to 1–2 pages

---

## 3. Fonts & Typography

- [ ] Use standard, widely-supported fonts: **Arial, Calibri, Georgia, Times New Roman, Helvetica**
- [ ] Avoid decorative/script fonts — may not parse and look unprofessional
- [ ] Font size: 10–12pt for body text, 14–16pt for name/headers
- [ ] Avoid excessive bold/italic/underline — use sparingly for emphasis only
- [ ] No colored text for body content (headings can use a safe accent color with good contrast)

---

## 4. Section Headers

Use **standard, exact-match section titles** so the parser maps them correctly:

- [ ] "Work Experience" or "Professional Experience" (not "My Journey" or "Where I've Been")
- [ ] "Education"
- [ ] "Skills" or "Technical Skills"
- [ ] "Certifications"
- [ ] "Summary" or "Professional Summary"
- [ ] "Projects" (if applicable)

Avoid creative renaming — this is one of the most common parsing failures.

---

## 5. Contact Information

- [ ] Full name
- [ ] Phone number
- [ ] Professional email address
- [ ] City, Country (full address not required/recommended)
- [ ] LinkedIn URL (optional but recommended)
- [ ] Portfolio/GitHub URL (if relevant to role)
- [ ] Placed as **plain text at the top of the document**, not inside a header/footer or graphic

---

## 6. No Graphics or Design Elements

- [ ] No photo/headshot (also avoids unconscious bias issues in many regions)
- [ ] No icons used as bullet points or section markers (parsers can't read icon meaning)
- [ ] No charts, graphs, or skill "rating bars" (e.g., 5-star skill ratings)
- [ ] No logos (company/school logos add nothing for parsing and can break layout)
- [ ] No background colors or watermarks

---

## 7. Bullet Points & Content Formatting

- [ ] Use simple round or square bullets (`•` or `-`) — avoid custom icon bullets
- [ ] Start bullets with strong action verbs (Led, Built, Managed, Designed, Implemented)
- [ ] Quantify achievements where possible ("Reduced incident response time by 40%")
- [ ] Keep bullets to 1–2 lines each
- [ ] Avoid walls of text — no paragraph-style job descriptions

---

## 8. Keyword Optimization

- [ ] Mirror keywords/phrases from the **specific job description** (exact terms, not just synonyms)
- [ ] Include both the acronym and full term where relevant (e.g., "Search Engine Optimization (SEO)")
- [ ] Weave keywords naturally into experience bullets — not just a dumped keyword list
- [ ] Include a dedicated **Skills** section listing hard skills, tools, and technologies
- [ ] Match job titles where accurate (if you were a "Software Engineer" and the posting says "Software Developer," consider aligning terminology if genuinely equivalent)
- [ ] Avoid keyword stuffing — unnatural repetition can hurt readability scoring with recruiters

---

## 9. Dates & Formatting Consistency

- [ ] Use a consistent date format throughout: `Jan 2023 – Present` or `01/2023 – Present`
- [ ] Always include month and year (not just year) for recent roles
- [ ] List "Present" for current roles, not blank or "ongoing"

---

## 10. Skills Section Best Practices

- [ ] Separate **hard/technical skills** from **soft skills**
- [ ] List specific tools, platforms, languages, certifications (e.g., "PostgreSQL," "ISO 27001," "React.js")
- [ ] Avoid vague entries like "Microsoft Office" alone — be specific ("Excel — pivot tables, VLOOKUP")
- [ ] Order skills by relevance to the target role, most important first

---

## 11. What to Avoid Entirely

- [ ] ❌ Multi-column/creative template layouts (Canva-style visual resumes)
- [ ] ❌ Tables for experience/skills
- [ ] ❌ Embedded images or infographics
- [ ] ❌ Headers/footers containing name or contact info
- [ ] ❌ Unusual bullet/icon fonts (Wingdings, emoji as bullets)
- [ ] ❌ Text over images or colored backgrounds
- [ ] ❌ Non-standard section names
- [ ] ❌ Scanned/flattened image-based PDFs

---

## 12. Final Pre-Submission Checks

- [ ] Copy-paste the entire resume into a plain text editor (Notepad) — if it reads cleanly in the correct order, it's ATS-safe
- [ ] Spell-check and grammar-check thoroughly
- [ ] Confirm the file opens correctly in both Word and a PDF viewer
- [ ] Verify all links (LinkedIn, portfolio) are live and correct
- [ ] Tailor the resume per application — generic resumes score lower on keyword match

---

## Quick Reference Summary

| Category | Golden Rule |
|---|---|
| Layout | Single column, reverse-chronological |
| Fonts | Arial/Calibri/Georgia/Times New Roman, 10–12pt |
| Sections | Use standard header names exactly |
| Graphics | None — no icons, photos, charts, or logos |
| Contact info | Plain text, not in header/footer |
| Keywords | Match the job description naturally |
| File type | .docx or text-based PDF |
| Length | 1–2 pages |
